# AI Team 0.2.12：安装和试用

这是通用说明包，包含分工、互审、作者回应、原审阅者复核、第三方判断、合并及中文表达要求。模型和工具来自使用者自己的环境。本包不附带账户或模型服务。

适合报告、方案、代码等需要留存依据、认真检查的重要成果。简单问答和小段改写通常不需要多人讨论；你明确要求互审时，仍按你的要求执行。

本版固定所有参与者收到的任务原文，分工备注另列；发现任务被转述成不同要求时先纠正。工具允许时，同一阶段的工作并行，减少重复背景说明和查询状态，不省略独立互审、作者回应及原审阅者复核。实际提速幅度需用相同任务比较，不能由安装成功推定。

0.2.8 补充成果检查：交付时说明检查依据、对应版本和未验证事项；可选脚本可核对加法及引用原句。它不证明来源真伪或业务效果，也不代替原有互审。用法见 [成果检查](references/delivery-checks.md)。

0.2.9 补充任务交接、来源核对和可选的本地调用次数记录；主助手统一委派，不让子 Agent 继续自行委派。版本检查以实际读取的安装文件为准；同时运行数量、会话保留能力和当前空闲数量分别判断，未调用就不宣称已验证。安装自检也核对本说明标题的版本，避免新包混入旧说明。

0.2.10 新增按任务复杂程度、出错影响、检查方式和资料范围生成分工建议。简单任务在能力相当时优先较低成本；高风险审阅不能仅凭便宜或 `general` 标签入选。主助手内部准备判断，不增加用户配置。具体规则及未实现的部分见 [任务与模型选择](references/task-routing.md)。这是本地规则，不代表已经接通其他工具或验证了真实模型的质量、费用。

## 最低要求

0.2.12 补充成果产出后的修改接续：把用户意见交回原作者，原审阅者复核新版本，保留原任务、旧成果与原 Memo，未受影响部分不重新生成。当前 Python 演示仅为确定性本地样例，没有验证任意自然语言理解或真实会话续接。见 [修改接续](references/feedback-continuation.md)。

完整使用只需要至少一个可用模型，以及能创建并继续三个独立子会话的工具。三个子会话分别作为 A、B、C，主助手负责安排和合并；C 只在有分歧时启用。不要求三个模型、三个软件或三个会话同时运行。

只有两个独立子会话时可以互审，但缺少完整第三方判断。没有独立子会话时只能做单助手自查。详细条件见 [通用使用条件](references/compatibility.md)。

## 安装

解压后保留完整 `ai-team` 文件夹，不要只拿走 `SKILL.md`。

把下面这段发给当前 AI 工具，并附上压缩包或解压文件夹路径：

> 请检查这个 AI Team Skill。若当前工具支持本地 Skill，安装到它实际认可的目录，已有同名版本先保留。若不支持自动发现，但能读取本地文件，就按完整 SKILL.md 及引用文件手动读取使用，并明确说明这一点。不能读取时告诉我缺少什么，不要宣称安装成功。先只检查文件和工具能力，不调用子 Agent、不改登录或模型配置。

检查工具能否发现或完整读取 Skill，再检查是否能够创建、保留并继续 A、B、C 三个独立身份。只是发现某个软件已经安装，不能据此推断它已能参与协作。

若有 Python 3.11 或更高版本，先运行：

```text
python -B <skill-dir>/scripts/self_check.py
```

`PASS` 只说明实际文件集合、包清单哈希、语法、分工降级和本地 Mock 输出通过，不会启动真实模型。它不能替代下面的宿主真人试用，也不是发布者签名或外部安全认证。

旧版、备份文件和使用记录放在当前 `ai-team` 文件夹之外。自检严格拒绝清单外文件，包括正常运行可能生成的 `__pycache__` 和 `.pyc`；发现缓存不等于发现恶意修改。所有附带脚本建议用 `python -B` 运行，避免新增缓存。已有缓存时保留原目录，优先从可信原包解压到一个新目录再检查；不要自动删除用户文件或重写清单来消除报错。

已安装文件有本地修改时，先保留原目录和修改内容，交由维护者在统一源文件中核对，再从新发布包更新。版本号相同而文件不同，应明确标为本地修改版；不能通过重算清单哈希把它当成原发布包。自检通过只说明文件符合该份清单，不证明修改合理或已被发布者确认。

待审版本工具默认不打印正文。主助手仍要把已核对的完整原文交给审阅者；`--include-content` 只在确有需要且输出保存范围合适时使用，具体见 [审阅约定](references/review-contract.md)。

## 试用

先做不调用模型的文件和接口检查，把下面这段发给已经能回应的主助手：

> 请读取实际安装的 AI Team Skill，报告路径和实际版本，并与同目录包清单核对。按当前工具说明，分别检查能否创建独立子会话、保留至少三个身份、回到原会话继续，以及可同时运行数量。未知就写未知，不从并发数量推断会话保留能力。先只检查，不启动真实子 Agent、Mock 或自检脚本，不修改文件或模型配置。

在能读取本包的会话中输入：

> 请按 AI Team Skill 处理一项虚构练习：月结目前需要五个自然日，希望缩短到四个自然日。问题是对账靠人工、差异记录分散、责任人不清。请给出三项优先事项、负责人岗位、步骤、完成标准和失败处理。先按现有能力安排角色并列明真实调用上限，等我确认后执行。结果只在聊天中展示。

确认这次角色和次数后，观察是否真的有独立子会话、审阅意见、逐条回应和复核。没有分歧时无需强行启用 C；若仍有未解决事项，应停止合并并交用户决定。

按 [真实 Agent 验收记录](references/real-agent-acceptance.md) 保存宿主版本、包 SHA、实际 Agent/会话 ID、调用状态、原始输出、耗时、成本和失败处理。至少覆盖三会话完整流程、两会话降级和无独立会话降级；本地 Mock 不能计入这三项。

## 有问题时

- 找不到 Skill：核对实际安装目录、完整文件夹和工具发现情况；手动读文件不等于自动发现。
- 没有子会话工具：记为只能单助手检查，不能伪装成多人互审。
- Python 缺失：只影响可选脚本，纯 Skill 使用不要求 Python。不要因此擅自安装新软件。
- 模型或工具调用失败：保留报错及失败步骤，先诊断，不反复重试或修改登录信息。分享记录前遮住敏感信息。
- 主对话尚未回应、未读取 Skill 就提示模型不受支持：这是工具启动问题，Skill 还没运行，不能靠再发一遍调用指令来修复。需通过工具支持的模型选择方式处理；AI Team 不自动改全局或旧对话设置。
- 子 Agent 提示模型不受支持：本次不再调用同一工具里的这个模型；按当前可用信息和已确认权限处理，不从历史任务里猜替代模型，不重跑已完成工作。
- 子 Agent 不能执行摘要计算命令：由主助手使用已获准的本地能力准备正文、版本和摘要，审阅者继续只读检查。主助手也无法计算时，明确版本核对未完成，不编造摘要，也不靠旧记忆跳过。具体方法见 [审阅约定](references/review-contract.md)。
- 缺少 `ai_team` 模块：检查 `scripts/ai_team/` 是否随完整包一起解压。

需要本地脚本演示时，可运行 `python -B <skill-dir>/scripts/demo.py "制定方案"`，需要 Python 3.11 或以上。它会标明 Mock，只证明本地演示可运行，不是实际业务成果。
