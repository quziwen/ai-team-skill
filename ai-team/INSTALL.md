# AI Team 0.2.5：安装和试用

这是通用说明包，包含分工、互审、作者回应、原审阅者复核、第三方判断、合并及中文表达要求。模型和工具来自使用者自己的环境。本包不附带账户或模型服务。

适合报告、方案、代码等需要留存依据、认真检查的重要成果。简单问答和小段改写通常不需要多人讨论；你明确要求互审时，仍按你的要求执行。

## 最低要求

完整使用只需要至少一个可用模型，以及能创建并继续三个独立子会话的工具。三个子会话分别作为 A、B、C，主助手负责安排和合并；C 只在有分歧时启用。不要求三个模型、三个软件或三个会话同时运行。

只有两个独立子会话时可以互审，但缺少完整第三方判断。没有独立子会话时只能做单助手自查。详细条件见 [通用使用条件](references/compatibility.md)。

## 安装

解压后保留完整 `ai-team` 文件夹，不要只拿走 `SKILL.md`。

把下面这段发给当前 AI 工具，并附上压缩包或解压文件夹路径：

> 请检查这个 AI Team Skill。若当前工具支持本地 Skill，安装到它实际认可的目录，已有同名版本先保留。若不支持自动发现，但能读取本地文件，就按完整 SKILL.md 及引用文件手动读取使用，并明确说明这一点。不能读取时告诉我缺少什么，不要宣称安装成功。先只检查文件和工具能力，不调用子 Agent、不改登录或模型配置。

检查工具能否发现或完整读取 Skill，再检查是否能够创建、保留并继续 A、B、C 三个独立身份。只是发现某个软件已经安装，不能据此推断它已能参与协作。

若有 Python 3.11 或更高版本，先运行：

```text
python <skill-dir>/scripts/self_check.py
```

`PASS` 只说明包清单、语法、分工降级和本地 Mock 输出通过，不会启动真实模型。它不能替代下面的宿主真人试用。

## 试用

在能读取本包的会话中输入：

> 请按 AI Team Skill 处理一项虚构练习：月结目前需要五个自然日，希望缩短到四个自然日。问题是对账靠人工、差异记录分散、责任人不清。请给出三项优先事项、负责人岗位、步骤、完成标准和失败处理。先按现有能力安排角色并列明真实调用上限，等我确认后执行。结果只在聊天中展示。

确认这次角色和次数后，观察是否真的有独立子会话、审阅意见、逐条回应和复核。没有分歧时无需强行启用 C；若仍有未解决事项，应停止合并并交用户决定。

按 [真实 Agent 验收记录](references/real-agent-acceptance.md) 保存宿主版本、包 SHA、实际 Agent/会话 ID、调用状态、原始输出、耗时、成本和失败处理。至少覆盖三会话完整流程、两会话降级和无独立会话降级；本地 Mock 不能计入这三项。

## 有问题时

- 找不到 Skill：核对实际安装目录、完整文件夹和工具发现情况；手动读文件不等于自动发现。
- 没有子会话工具：记为只能单助手检查，不能伪装成多人互审。
- Python 缺失：只影响可选脚本，纯 Skill 使用不要求 Python。不要因此擅自安装新软件。
- 模型或工具调用失败：保留报错及失败步骤，先诊断，不反复重试或修改登录信息。分享记录前遮住敏感信息。
- 主对话尚未回应、未读取 Skill 就提示模型不受支持：这是工具启动问题，Skill 还没运行，不能靠再发一遍调用指令来修复。需通过工具支持的模型选择方式处理；AI Team 不自动改全局或旧对话设置。
- 子 Agent 提示模型不受支持：本次不再调用同一工具里的这个模型；按当前可用信息和已确认权限处理，不从历史任务里猜替代模型，不重跑已完成工作。
- 子 Agent 不能执行摘要计算命令：由主助手使用已获准的本地能力准备正文、版本和摘要，审阅者继续只读检查。主助手也无法计算时，明确版本核对未完成，不编造摘要，也不靠旧记忆跳过。具体方法见 [审阅约定](references/review-contract.md)。
- 缺少 `ai_team` 模块：检查 `scripts/ai_team/` 是否随完整包一起解压。

需要本地脚本演示时，可运行 `python <skill-dir>/scripts/demo.py "制定方案"`，需要 Python 3.11 或以上。它会标明 Mock，只证明本地演示可运行，不是实际业务成果。
