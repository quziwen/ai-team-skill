# 按任务选择工具和模型

## 用户不用填参数

主助手理解任务时一起判断，不为分类增加一次模型调用：

| 判断 | 取值 | 怎样用 |
| --- | --- | --- |
| 要求是否明确 `clarity` | clear / ambiguous / unknown | 含糊或未知时要求有复杂推理能力 |
| 执行复杂程度 `complexity` | routine / complex / unknown | 复杂或未知时不按简单执行安排 |
| 出错影响 `consequence` | low / high / unknown | 高影响或未知时要求能审阅高风险结果 |
| 检查方式 `verification` | objective / judgment / unknown | 不能靠确定结果检查时要求判断型审阅能力 |
| 资料范围 `data_scope` | public / business / unknown | 非公开或未知时必须说明获准处理材料的工具 |

判断依据 `basis` 简短写在已有任务记录中，只说明为什么这样判断，不放原始业务数据。缺少影响完成标准的信息才问用户；不能为了省钱把未知填成简单、低风险或公开。`public` 仅用于实际允许候选工具读取的输入；材料脱敏不自动等于公开。权限没有变化时复用有效授权，不反复确认。

先看有没有必要使用多 Agent。固定计算、格式转换等优先使用获准的本地程序；脚本分工建议只会提醒，不会替用户运行程序。用户明确要求独立互审时保留原流程。

## 选择顺序

1. 只使用当次可调用、可保留并继续身份的工具与模型组合，过滤当前不可用项。
2. `allowed_tool_ids` 是本次全部输入和审阅资料可以交给的工具编号，适用于 A、B、C。空数组表示都不允许；非公开或未知资料未填此项时停止安排。名单不能授予新权限，也不替代用户原有的数据要求。
3. 检查原有工作与 review / arbitration 能力，再补下面的要求。能力依据必须为 measured 或 declared；unknown 不参与新版选择。declared 是有出处的说明或用户指定，不是已实测。
4. 能力覆盖和依据优先，然后考虑本次工具偏好，最后比较已知相对成本。没有偏好就直接比较成本；未知费用不按免费处理。这不是实际费用核算，也不保证总费用最优。

| 情况 | 额外能力标签 |
| --- | --- |
| 要求含糊，或执行复杂，或这两项未知 | advanced_reasoning |
| 出错影响高或未知 | high_impact_review |
| 需要判断才能检查，或检查方式未知 | judgment_review |

标签由同类实测或明确能力说明支持，不能从价格、厂商或模型名称推断。便宜模型确实具备所需能力也能入选；昂贵模型缺少能力依据也不行。`general` 不覆盖这些额外要求。

本小版本沿用 A、B 都产出并互审的安排，因此两人都要满足本任务的审阅要求，C 也不能例外。这是偏谨慎的任务级判断，尚未分别给每个子任务自动判断难度。不能为了让 B 用便宜模型，就忽略 B 还要审 A。也不新增专职审阅身份、讨论轮数或真实调用。

## 资料怎么传

默认只传完成工作需要的内容。碰业务数据的任务在获准工具内读取、计算、核对；外面的主助手优先接收获准摘要、方法、检查结果及匿名问题编号。原始数字和证据在原处保留，摘要也应检查是否包含敏感内容。

少传资料不能损害审阅：看不到必要依据就明确“尚未核验”，不能只凭另一 Agent 说通过就通过。可以在获准工具内准备足够上下文，或在现有授权范围内提供最少必要内容；确需扩大敏感资料范围才询问。工具偏好是偏好，不是永远禁止其他获准工具。

当前输入是整项任务共用范围，不支持同一次建议中让 A 只收摘要、B 收原始数据。混合任务先将规划所需的公开或获准摘要与原始数据工作分开，由主助手在已有任务安排中分别处理，并保留完全一致的用户任务原文。未获准接收正文的主助手不能默认获得完整报告；可由获准工具整理数据部分，主助手只汇总获准返回的内容。输出的 `merger=current_assistant` 只代表协调责任，不授予读取或合并原始材料的权限。

这些是选择规则，不是操作系统权限控制、自动脱敏或沙箱；助手仍需在每次实际交接前检查资料和授权。

## 内部输入示例

在原有任务和 tools 输入旁增加下面字段。编号仅为示意，必须换成当次已知的真实工具编号，不代表已安装任何工具：

```json
{
  "task_profile": {
    "basis": "公开的练习材料，步骤确定，可按已知结果检查。",
    "clarity": "clear",
    "complexity": "routine",
    "consequence": "low",
    "verification": "objective",
    "data_scope": "public",
    "allowed_tool_ids": ["planning-tool", "execution-tool"],
    "preferred_reasoning_tools": ["planning-tool"],
    "preferred_execution_tools": ["execution-tool"]
  }
}
```

`preferred_reasoning_tools` 用于 A 和按需准备的 C，`preferred_execution_tools` 用于 B，只在能力及依据相当时优先使用；不覆盖允许范围、不改变当前主助手模型、不修改后端配置。偏好缺失时用空数组。未指定公开资料的工具限制时 `allowed_tool_ids` 可为 null。工具不足、能力不够、数据范围不明会在建议里说明，不自动另接服务。

旧输入不含 `task_profile` 时保留原有行为，以兼容已有调用和测试；不能把旧输入结果当作经过新版检查。普通 Mock CLI 的行为未改。

## 失败后和真实验收

先区分缺资料、要求不清、工具失败与能力不足；不能一失败就换更贵模型。沿用原有一次回应和复核；没有新依据或仍不满足必要要求时停止，保留待处理事项。新模型、新角色、额外调用或扩大资料范围，若不在本次有效授权内，须先询问；不得悄悄换会话冒充原审阅者。

本脚本不执行模型升级、重试、资料传递或自动调用。实际费用和耗时仍由 [真实验收记录](real-agent-acceptance.md) 记录，并包括人工介入、返工和失败调用。未知写未知；本地规则测试不能证明省钱、提速或真实审阅质量。
