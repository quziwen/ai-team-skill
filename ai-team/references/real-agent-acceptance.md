# 真实 Agent 验收记录

本文件用于验证宿主是否真的创建并保留独立 Agent 会话。包内 `self_check.py`、Mock 演示、代码测试和“发现了 Skill”都不能替代该验收。

## 每次测试必须保留

- 测试时间、宿主名称与版本、操作端、Skill 版本与 ZIP SHA-256。
- 当前真实可选模型清单和失败模型；不得从旧对话推定。
- A、B、C 的真实会话或 Agent ID、各自角色、是否保留上下文、是否并行。
- 用户确认的调用次数上限、文件写入范围和外部动作权限。
- 每次调用的开始/结束状态、原始输出或可追溯链接、耗时、token/费用（宿主可提供时）。
- 交叉审阅意见编号、作者逐条回应、原审阅者复核，以及仍有分歧时 C 的判断。
- 主助手使用什么已获准工具准备待审版本；原正文、版本、`content_sha256` 和 CCRL `artifact_sha256` 是否匹配。至少验证一次“子 Agent 不执行命令，主助手完成摘要计算”；主助手也无法计算时，必须明确版本核对未完成，不能靠记忆跳过。
- 失败、重试和降级记录；失败调用也计入上限。

分享记录前移除密钥、token、Cookie、个人目录、内部链接和敏感业务数据。

## 三个必测场景

| 场景 | 真实前提 | 预期结果 | 不能声称 |
|---|---|---|---|
| 三会话完整流程 | 至少一个真实可用模型；三个可保留独立会话 | A/B 独立产出并互审；有未解决分歧才启用 C；关闭后由主助手合并 | 无 C 调用时不能写“C 已复核” |
| 两会话降级 | 只有两个可保留独立会话 | A/B 互审；未解决分歧交用户；标明 `peer_review_only` | 不能写“完整三方流程” |
| 无独立会话降级 | 零或一个独立会话 | 只给单助手草稿和自查；标明 `self_check_only` | 不能扮演多人并声称互审 |

## 结果口径

- `本地自检通过`：仅包内确定性检查通过。
- `宿主流程通过`：上述三个场景在某个明确宿主版本真实运行并留证。
- `业务有效性待验证`：尚未由实际使用者在真实任务中评价质量、节省时间和复用价值。
- `正式验收通过`：只有事先约定的验收人、范围和标准全部满足后才能使用。

不同宿主、模型或版本要分别记录；一个宿主的成功不能外推到全部平台。
