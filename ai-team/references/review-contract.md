# AI Team 内部审阅约定

本约定使用 AI Team 现有 CCRL 做法。CCRL 负责固定审阅对象、保存原始意见、逐条回应及复核；任务安排、第三方判断和合并由 AI Team 负责。

## 怎样提出和回应质疑

先核对成果是否服务用户已确认的目标，不只检查文字和格式。质疑要有具体依据，说明会影响什么、建议怎样改；证据不足就说明还需核实什么，不把猜测当事实。没有实质问题就通过，不为显得独立而凑反对意见。作者和审阅者都按证据判断，不因对方或用户坚持就放弃有依据的结论；有新事实或发现自己出错时应修正。用户的偏好和目标由用户决定，不能当作事实错误来否定；合理取舍不强行争成对错。

## 审阅记录

每份成果记录 `artifact_id`、`assignment_id`、`author_id`、`version` 和正文。主助手负责准备固定版本并计算摘要，不把这个动作交给无命令权限的审阅者，也不要求模型凭文字猜出摘要。

主助手取得本次完整正文后，使用已有授权的本地能力计算，保留换行、空格和所有字符，不在计算前做格式转换。将同一份正文、成果编号、版本及计算结果一起交给审阅者；发送前核对正文逐字一致。读取文件不等于获准运行命令，不因为本规则擅自扩大工具权限。

- `content_sha256`：仅对正文的 UTF-8 字节计算 SHA-256，用于核对原文是否变化。
- `artifact_sha256`：沿用 CCRL 的 `artifact_sha256(Artifact)`，摘要还包括成果编号、子任务编号、作者和版本。Review Memo 的 `reviewed_sha256` 对应这个值，不拿正文摘要替代它。使用已有 CCRL 时继续由程序计算和校验，不改变旧格式。

可选工具：主助手将 `{"id":"成果编号","assignment_id":"子任务编号","author_id":"作者身份","version":1,"content":"完整原正文"}` 经标准输入送入 `python -B <skill-dir>/scripts/prepare_review.py`。这些字段由助手整理，用户不用填写。工具复用 CCRL 算法，返回原正文、两种摘要及 `ready_for_review`；整个 JSON 最多 120 KiB，不读取任意路径、不写文件、不启动 Agent。JSON 转义可以变化，解析后的正文字符不得变化。只有退出码为 0 且 `ready_for_review=true`，才可继续交给审阅者；这只表示版本准备完成，不表示内容正确或审阅通过。

没有获准使用的计算能力时，明确记录 `needs_version_check`，保留草稿与已有意见，停止以完整审阅结果交付。不能让模型编造 SHA-256，不能把旧摘要、旧记忆或“不再报错”当作本次核对成功。`--hash-unavailable` 可供主助手记录此状态，退出码为 2 且不返回摘要；没有脚本运行能力时直接如实说明，不必强行运行。补齐条件后重新准备本次版本；超出原有授权才询问用户。

作者修改正文后，主助手为新版本重新计算；成果身份或版本变化也必须重新计算 CCRL 摘要。旧 Memo 与旧摘要保留，原审阅者复核的是新版本，不覆盖历史记录。

每份 Review Memo 固定记录审阅者、成果编号、版本、成果摘要（`reviewed_sha256`）、范围和完成标准。意见包含：

- `finding_id`：在本份 Memo 中唯一。
- `problem`、`evidence`、`suggestion`：具体问题、支持依据、修改建议。
- `severity`：critical、major 或 minor。
- 有分歧时补充主题及双方立场，不能删掉少数意见的事实依据。

没有发现问题时明确写 `no_findings`；读取失败、无法检查、缺少材料不能写成没有问题。原始 Memo 保留，后续处理追加新记录，不覆盖原文。

## 回应和复核

作者对每条意见选择 accept、reject 或 clarify，并说明理由；接受修改时给出新的完整正文和版本号，不能只说“已修改”。原审阅者核对实际新版本，对每条意见确认已解决、撤回、仍有分歧或需要用户决定。

检查每条意见都恰好回应和复核一次，身份、成果和版本相符。缺项、重复项、换人、空正文或错版本必须停止。需要修改却没有实质改动，不能确认已解决。纯粹反驳或请求澄清时保留原成果版本。

## 第三方判断和合并

C 与争议双方不同，对每条剩余意见分别给出结论、理由和是否解决。无法核验的事实、用户未明确的预算或业务取舍，应保留为需用户决定，不能凭投票抹去。

只把仍未解决的事项交给用户，包含双方观点、C 的判断及需要决定的具体问题。只要还剩一条未解决事项，就停止最终合并。已确认的部分保留为阶段成果。

没有剩余事项时，当前助手合并所有确认过的成果与第三方结论。Python `AITeam.run()` 还会检查确认正文是否被完整纳入，使用该程序时保持其检查规则；不要在程序外改写后声称仍通过原检查。

## 实际执行与本地示例

宿主子 Agent 的真实返回应作为本次任务记录。本地 Mock 只用于演示流程，不能补进真实作者回应、复核或第三方判断中。调用失败就记录失败；没有结果不能编造“通过”。

包内 Python 保留现有数据类型和校验实现，需要这些类型时从 `scripts/ai_team/contracts.py`、`ccrl.py` 和 `runner_backend.py` 读取；它们不是已连接的真实模型服务。
