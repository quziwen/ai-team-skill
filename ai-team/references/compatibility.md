# 通用使用条件

本包不要求指定厂商、工具名称或模型名称。先按实际工具能力判断能做什么，再选角色。以下是本包的最低条件，不是任何工具或模型已经通过测试的声明。

## 安装或读取说明

- 工具支持 `SKILL.md`：把完整 `ai-team` 文件夹放入该工具认可的 Skill 目录，通过其支持的方式发现和调用。
- 工具不支持自动发现 Skill，但可以读取本地 Markdown 和相对引用：保留完整文件夹，让助手按 `SKILL.md` 执行。记录为“手动读取使用”，不能说已经被工具自动发现。
- 工具既不能安装 Skill，也不能完整读取说明和必要材料：当前不能使用本包。不能仅粘贴角色名就声称已经安装或运行。

不要写死用户目录、操作系统或模型配置。安装者已有同名包时保留旧版。具体安装目录以其工具实际文档或安装入口为准，找不到依据时先说明缺少信息。

## 完整多 Agent 使用的最低要求

| 对象 | 最低需要什么 |
| --- | --- |
| 可用模型 | 至少 1 个，能理解本次任务和必要资料、返回可用结果；可为本地模型或已有账户下的模型 |
| AI 工具 | 至少 1 个，当前主助手能使用它创建并继续独立子会话、取得真实返回；可以是原生能力，也可以是已有可用连接 |
| 独立子会话 | 能创建并保留至少 3 个身份：A、B、C；不包含负责安排和合并的当前主助手 |
| 同时运行数量 | 1 个也可以，依次执行；“能保留三个会话”不要求三个同时运行 |
| 审阅资料 | 能把固定版本正文、任务要求及必要依据交给审阅者，并保留原始意见和后续回应 |
| Python | 纯 Skill 使用不需要；可选分工和 Mock 脚本需要 Python 3.11 或更高版本 |

因此，完整流程通常是一个主助手，加上三个按需使用的子 Agent 身份。它们可以全部使用同一个模型、同一个工具。A、B 产出并互审；C 只在尚有分歧时启动；主助手最后合并。

三个身份也可以分布在多个工具中，但这些工具必须能被当前助手实际调用，并能回到原会话继续工作。安装了三个软件、或者手工打开三个无法相互交接的聊天窗口，不等于具备自动协作能力。

模型数量不是效果保证。模型是否够用还取决于任务复杂度、上下文、资料质量和实际试用结果。同一模型的不同会话可能有相似盲点，多个模型也不保证判断正确。

## 条件不足时怎样处理

| 情况 | 本次可以做什么 | 不能声称什么 |
| --- | --- | --- |
| 三个独立身份及任务能力齐全 | 按能力说明尝试完整流程 | 不能在实际调用前声称模型已通或效果已验证 |
| 只能保留两个独立身份，或缺少判断能力 | 双人互审；未解决事项交用户 | 不能声称具备完整第三方判断功能 |
| 只有一个会话，或无法回到原作者和审阅者 | 当前助手产出和自查 | 不能把分角色写作当成独立互审 |
| 没有可调用的模型组合，或不能读取必要材料 | 列出缺失条件 | 不能编造子 Agent、模型或通过记录 |

做代码实现还需要相应的文件、执行和测试工具；仅有模型数量并不足够。其他任务同样按实际交付物检查所需工具和权限。

## 发现与确认

当前助手先查自己真正可调用的工具及参数说明，读取非敏感能力信息；必要时只查用户明确提到的软件是否存在。没有公开可用模型列表时，允许记录“当前默认模型、专项能力未知”，不能扫描登录文件来猜。

模型信息每次新任务重新核对，旧对话曾用过的编号不自动成为当前候选。已知不受当前工具或账户支持的模型应排除；未知就说明未知，不以额外的未授权调用来试。详细做法见 [角色安排](agent-assignment.md)。

Skill 必须先被一个能够正常回应的主对话读取，才能安排子 Agent。主对话在加载 Skill 前就因旧模型设置而报错时，本包无法在启动前切换模型，也不能保证任何软件都自动修正这类设置。软件自身的模型停用、权限变化和服务故障，不等于 Skill 已执行失败。

把候选分为：当前原生可调用、已连接可调用、仅已安装、当前不可用。只安排前两种。真正发起子 Agent 请求仍按本次任务确认的角色和次数执行；失败记入次数，说明哪里未验证。

不要为“通用”自动遍历整个电脑、安装 SDK、注册账户、读取凭证、修改模型配置或尝试未确认的真实调用。本包没有实现任意外部 CLI 的通用调用器；没有可用连接的工具先保留为候选。

用户只需看到简短结果：能否读取 Skill、是否符合完整使用条件、这次怎样分工、还缺什么。工具和模型清单等内部信息由助手整理，用户不用手填。
