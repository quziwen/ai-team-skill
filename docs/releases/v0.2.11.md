# AI Team Skill v0.2.11

几个 Agent 都同意，不代表结果就正确。本次把必要证据的检查接到最终交付判断：必要项失败或缺少依据时，保留阶段成果，不强行合并。

## 本次改动

- 开始任务时区分用户已确认的必要要求与后续建议，不擅自增加完成标准。
- 作者修改后检查最新成果及版本，旧版本检查记录不直接沿用。
- 可选 Python 接入在必要项失败或未验证时返回 `needs_verification`，保留逐项结果，不调用合并者。缺证据不交给第三方投票。
- 本次发布也包含自 v0.2.8 以来的独立初稿、主助手统一委派、资料允许范围、按任务难度和实际能力分工等改进；不新增固定角色或讨论轮数。

默认 Mock 和旧调用方式保持兼容。Python 新增检查是可选接入；省略参数时不代表已经核验全部业务条件。纯 Skill 使用仍依赖宿主实际执行说明。

- 安装包自检通过。源码、冻结测试包和交付包的受管文件字节已核对。
- skill-test v0.4.2：三个只读 Codex CLI 执行样例完成，7 项独立内容评分通过；另外核对实际工具记录，3 项通过。

测试中每个执行会话实际使用冻结包的 `AITeam.run()`，不是手写完成状态。第三个样例由独立新上下文准备，评分者不继承开发讨论；工具过程检查由主协调者另存，不冒充独立评分。

首次自动运行被助手设定的用量阈值暂停，原报告保留；只补未执行样例及评分，没有改变判断标准。错误合计样例第一次终端输出有乱码，在同一执行会话调整编码后重跑本地程序，两次都停止合并。默认测试配置的旧可执行文件路径失效，使用项目内临时运行配置修正，未修改全局登录或认证。

## 尚未验证

三个样例调用模型来测试 Skill，但作者和审阅者返回是本地预设 Mock。这不是实际 A、B、C 互审、回应修订和裁决全流程验收，也不是业务验收。未验证所有宿主的实际模型表现、自然触发率、长期稳定性、来源真伪、完整输入或总成本改善。

三次 CLI 执行记录合计约 352 秒，不是整轮工作时间；记录 Token 合计 789,083，包含缓存输入，不包含主协调、原生样例准备与评分。实际费用未知，不据此推算节省比例。

计算正确不能证明输入真实，引用匹配不能证明结论成立。必要要求是否齐全仍需主助手根据用户任务明确；工具不会自动发现全部关键事实，也不提供操作系统权限隔离。
